# Mutation Error Handling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add consistent error toast feedback to all ~33 frontend mutation call sites via a `mutate` utility and Sonner toast library.

**Architecture:** Install Sonner (toast library) via shadcn for theming, create a thin `lib/mutate.ts` utility that wraps any `api.POST/PATCH/PUT/DELETE` call and fires `toast.error` on failure, then wire all existing mutation call sites to use it. No global state, no hooks — just a single async function.

**Tech Stack:** Sonner (toast), shadcn Sonner component for theming, Vitest for unit testing the utility.

```typescript
import { toast } from "sonner"

export async function mutate<T>(
  fn: () => Promise<{ data?: T; error?: unknown; response: Response }>,
  options?: { errorMessage?: string },
): Promise<{ data: T | undefined; error: unknown }> {
  const result = await fn()
  if (result.error !== undefined) {
    toast.error(options?.errorMessage ?? "Something went wrong. Please try again.")
  }
  return { data: result.data, error: result.error }
}
```
